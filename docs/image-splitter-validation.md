首次验收：2026-08-31；最近交互回归复核：2026-10-08。整体视觉继续沿用 v3，自由编辑与切片预览共用工作区。当前修复及验收边界见下节；原生系统保存、手机真机及全项目类型检查问题仍保留。

## 2026-10-08 手机自由裁切拖动回归

- 问题设备由用户确认为 iPhone / Safari。本轮使用真实浏览器引擎和触控协议复现，未连接 iPhone 真机。
- 根因一：开始拖动会使导出准备状态失效，状态提示或 ZIP 回退入口消失，页面高度缩短；靠近页面底部时，浏览器钳制滚动位置，滑轨随之移动。修复前 Chromium 与 WebKit 均捕获 42–50px 页面跳动。
- 根因二：相邻切线拉近后，44px 滑块命中区重叠，已激活滑块的高层级遮住下一条。320px 横切连续调整稳定复现下一条切线不动；片缝控件存在同类命中风险。
- 修复：拖动期间保留工作区按下时的高度，网格内容保持顶部对齐，松手恢复正常布局；滑块与片缝的重叠区域根据实际中心距离选择切线，非重叠区域保留原索引，保存按钮仍按明确片序操作。
- 永久浏览器守卫：`src/components/image-splitter/interaction.browser.test.mjs`。覆盖 Chromium / WebKit、1280 / 390 / 320px、两个裁切方向、连续拖动两条滑块及片缝、拖动期间滚动稳定、松手释放预留高度、切片重新准备以及整页不横向溢出。正式构建预览 12/12 通过，无跳过；专项 Node 测试 77/77 通过。
- 工具校验、静态构建、offline、39 个 PWA manifest 校验通过。完整 `npm run typecheck` 因 Node 堆内存不足退出；图片裁切组件及其依赖的定向 `tsc --noEmit` 检查通过，未把它当作全项目检查通过。

浏览器回归使用已有 Playwright 测试安装，不增加工具运行时依赖。先启动正式预览，避免 Astro 开发工具栏遮挡窄屏控件：

```sh

ASTRO_TELEMETRY_DISABLED=1 npm run preview -- --host 127.0.0.1 --port 4323
# 在另一个终端运行；需要已安装相应浏览器运行时。
```

已有共享 Playwright 安装可通过 `IMAGE_SPLITTER_PLAYWRIGHT_MODULE` 指定模块路径；已有浏览器可通过 `IMAGE_SPLITTER_BROWSER_EXECUTABLE` 指定可执行文件。`IMAGE_SPLITTER_TEST_URL` 可覆盖预览地址。未找到 Playwright 时用例明确跳过，不能算作浏览器验收通过。

## 交付行为

- 桌面和手机共用一个原生图像文件输入；上传／更换按钮直接触发系统选择器，选择后自动处理。
- 纵向／横向，默认纵向；3／4／自定 2–32 张，默认 3 张；自定步进器原位替换按钮。
- 均等／自由切分；页面只渲染一个“预览与调整”工作区。自由模式可直接拖动真实切片之间的间隙，纵向切割另用图片下方横滑条精调，横向切割另用图片右侧竖滑条精调。滑块、片缝、拖动坐标及辅助功能方向同步，对称联动及中间切线独立移动。
- 选图预览按上传区可用宽度自适应、最多 32rem，高度随原图比例变化；没有固定框内白边，也不裁掉图像内容。
- 分割预览保留真实比例和片序；两方向图像间隙均为 6px。纵切按源宽度比例铺满、整排同高，编号保存按钮在下方独立网格换行；横切纵排且同宽，右侧保存栏不参与图片行高。各按钮能在对应图片中心放下且不挤碰时逐片居中，并联动两栏滚动；否则紧密堆叠、独立滚动。聚焦／悬停按钮时高亮精确对应片，必要时仅在预览内部显示目标。
- 分割预览高度随内容展开，保护上限取一屏高度和预览布局宽度两倍中的较大值；常见横竖图完整显示，超长图才保留内部滚动。桌面与手机共用这一规则。
- 单张原尺寸 PNG，以及整组目录保存／系统分享／明确的 ZIP 兼容操作。系统接口取消不触发额外下载，部分写入不报全部成功。
- 英语、日语、简体中文；纯浏览器计算、无图像持久化、无新增依赖或外部网络请求。

主要实现位于 `src/tools/image-splitter/`、`src/lib/image-splitter/`、`src/components/ImageSplitterTool.tsx` 及同名 CSS。公共接入仅修改两个工具 registry、`ToolPlayground.tsx` 和该工具的详情标题分支。

该轮实际浏览器检查还发现两处按钮尺寸边界并完成修正：网格隐式行高停在 44px，而两位数英文按钮换行后实际为 56px；右栏改为不可压缩的 Flex 单列后，按钮间距稳定在约 8.80px，不再相碰。日文按钮实际为 66px，8192×2 极矮图的保存栏由固定最低 52px 自适应到 74px，完整容纳一枚按钮和上下内边距；这只改变独立栏的最低可见高度，不改变子图高度或 3px 图片间隙。日文六片在 1280px 时逐片居中、691px 时自动紧凑，393px 的 32 片无重叠。纯布局测试覆盖临界间距、不等高自由裁切、局部拥挤、换行、末片超高和不可测尺寸；源码守卫只检查接线，不能替代上述浏览器证据。未修改像素上限、导出逻辑、其他工具或原生系统能力。

预览高度再次按用户反馈放宽：原桌面 `min(70vh, 32rem)`、手机 `min(65vh, 28rem)` 两处上限过早截住正常图片；原页面完整内容约 711px，却只有 512px 可见。现在以预览布局为宽度查询容器，统一使用 `max(100vh, 200cqw)`，不设置固定高度、不缩小切片，也不改变独立按钮轨道。新增永久契约守卫检查容器单位归属和统一规则，并使用样式声明中的参数验证 4:3、3:4、9:16 比例能够展开、超长图仍有边界；这是源码／计算契约，不替代浏览器证据。

本次 Chromium 的 11 个独立布局场景覆盖 393／691／1466px、4:3 与 3:4 图、六片及三十二片、连续 1px 自由横切和两方向超长图。普通图片均无内部纵向滚动，图片间隙均为 3px、交叉轴尺寸差为 0px，无整页横向溢出，所有编号保存按钮目标正确且已就绪；横切六片在 691px 居中、393px 紧凑，居中最大偏差约 0.04px。128×2048 合成超长图在 393px 下两方向仍限制为 852px；横切聚焦 Save 3 后，准确高亮第三片，图片与保存栏同步滚至 2071px。测试结束后恢复视口并关闭临时页，用户原图及三等分配置保留。

同形限高扫描检查了图像预览的两处规则并合并修复；另外五处全局限高属于文件列表、文本结果、语音分块和存储文本预览，不是切片图像布局，保持不变。裁切编辑器的工作区尺寸限制同样未改动。本次只调整图像预览 CSS、永久契约测试及本验收记录；像素上限、解码、导出和原生保存没有变化。

后续按最新反馈调整自由切割的滑条方向，取代原开发计划中“横切仍使用下方横滑条”的约定，其他 v3 布局不变。根因是 `FreeCutEditor` 固定使用横轨、`left` 位置及 `aria-orientation="horizontal"`，而两个轨道坐标分支也始终读取 `clientX / width`。现将横切的滑条置于图片右侧，滑块按 `top` 定位、坐标取 `clientY / height`；纵切继续使用下方横轨和 X 坐标。竖轨上下边缘对齐实际图片，保留 44×44px 触控目标及端点留白，不让原横轨的最低高度撑高图片。

2026-09-04 的合并设计继续保留上述方向规则，但删除重复的完整原图编辑画布。自由模式直接在真实切片之间放置 2rem 宽／高的透明命中区，片缝视觉线仅 1px，激活时 2px；指针坐标会先扣除全部 6px 固定片缝，再映射回源像素，因此拖动片缝和滑条共享同一组整数边界。纵切的保存按钮仍位于下方独立网格，横切仍保留右侧独立保存栏；按钮不再插入切片卡片，所以不会改变图片连续预览。均等模式复用同一个预览组件，但隐藏对称开关、片缝拖动和滑条。

输入计算放在本工具的小型纯函数 `src/components/image-splitter/cut-input.ts`：拖动与点击空白轨道共享主轴映射，邻近判断仍保留未取整位置与等距时的稳定顺序；点中已有滑块仍使用其明确索引。竖轨的 ↑／↓ 和 PageUp／PageDown 按画面向上／向下移动，横轨保留原快捷键语义；Home／End 及相邻切线边界仍由原状态逻辑约束。主轴切换、指针捕获和结束清理沿用既有处理，没有改动预览高度、保存栏、解码或导出。
